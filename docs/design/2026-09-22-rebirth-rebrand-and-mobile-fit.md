# 重生题材改版与手机单屏适配方案（2026-09-22）

> 状态：已按本方案完成游戏本身的首轮改版；具体实现、调整及验收边界见[实施记录](2026-09-22-rebirth-implementation-report.md)。微信打包与发布按用户最新要求暂不处理。
> 依据：用户的名称、描述、风格与无滚动要求，以及当前仓库页面和组件实现。
> 目标：让玩家一眼理解“重活一世，以诗词改命”，在手机一屏内完成浏览、答题和结算。

## 1. 评估结论

原方案方向可用，但以下假设需要纠正：

| 原方案问题 | 本次调整 |
| --- | --- |
| 将候选名写成“用户否决”“拍板结论” | 当前任务未提供这些确认依据，改为推荐与取舍，不代替用户确认 |
| 主要靠改标题、序章和角标体现风格 | 同步调整首页、人物舞台、成长目标、操作层级和结算反馈 |
| 默认列表页可以长滚动 | 所有游戏页面及弹层默认无横纵滚动；列表采用分页或分屏 |
| 用 overflow-hidden 和根节点高度证明适配 | 增加内容完整性、遮挡、点击和分页可达检查，不能靠裁切通过验收 |
| 11 个官阶横排挤在一行 | 主页只展示当前、下一阶与迷雾概览；完整路线另开分页面板 |
| 认为对局页基本放得下 | 揭晓态会追加整块反馈，是重点重构对象 |
| 每阶段重复全量检查并自动推送分支 | 阶段内针对性验证，完整改版统一全量验证；不预设推送、部署或分支同步 |

代码核查事实：

- 首页为正方形封面、大间距和模式卡纵向堆叠，底部展示了接口加密等实现说明。
- 官途页包含身份卡、纵向路线、竞猜、事件及多个通栏按钮，不能仅靠缩小 padding 解决。
- 对局 REVEAL 在四个选项之后追加反馈气泡；结算还会叠加成就、事件和分享长图。
- ShareCardView 自动展示 750×1200 分享图；新长标题不能直接沿用单行 54px 绘制。
- cover-title.py 的标题层同时含“谜盒”和“诗词升官”，两处都需处理。脚本声明 cover_v1.png 为干净底图，实施前仍需目视确认。
- 当前 package.json 未配置 Playwright 脚本，浏览器验收需补齐运行方式，不能当作已完成检查。

以上是静态代码评估，尚无本次实机截图与运行测量结果。

## 2. 名称与描述

### 2.1 推荐名称：《重生：我靠诗词问鼎天下》

原名《重生我靠诗词当上皇帝》目标直接、故事感强，加入冒号后更易读。“当上皇帝”较口语，也提前公开现有隐藏终点。“问鼎天下”保留逆袭野心，更贴合古风表达，但目标没有原名直白，这是明确取舍。

| 名称 | 判断 |
| --- | --- |
| 重生：我靠诗词当上皇帝 | 最接近用户原意；如采用，需明确调整为“公开目标、隐藏解锁条件”，不能声称终点仍完全保密 |
| **重生：我靠诗词问鼎天下** | **推荐正式名**：重生点题材、诗词点玩法、问鼎点目标，兼容现有终点显隐设计 |
| 诗词逆命 | 推荐界面短名，适合窄屏；单独作正式名时，重生题材不如长名清楚 |

这是创作与产品定位判断，不包含名称唯一性、商标或市场表现结论。后续设计按推荐正式名展开。

### 2.2 推荐文案

原句“改变一起”应为“改变一切”；同时压缩开头，补足诗词玩法与布衣起步的信息。

| 场景 | 文案 |
| --- | --- |
| 完整简介 / metadata | **既然上天让我重活一世，这一次，我要以诗词改写命运。从一介布衣到名动天下，步步登高，问鼎巅峰。** |
| 首页主标语 | **重活一世，以诗词改命。** |
| 首页玩法说明 | 答诗词，积功名，从布衣一步步登高。 |
| 首次进入按钮 | 开启这一世 |
| 已有进度入口 | 续写这一世 |
| 返回按钮 | 返回官途 |
| 分享标题 | 重生：我靠诗词问鼎天下（两行排版） |

正式名统一使用中文冒号，顶栏使用“诗词逆命”，不再引入第三套简称。首页仅保留一个完整标题，避免封面、卡片、副题三次重复。存档状态沿用现有玩家状态，加载期间用中性“进入游戏”，不为按钮文案新增接口。

“重生”是叙事设定，不新增轮回、删档重开或转生系统，已有存档保留。保留“研习、科考、功名”等明确的操作词；不承诺宫斗、经营、征战或剧情分支。保留“架空成长，非真实官制”短说明，前台移除接口加密等实现细节。

## 3. 紧扣主题的风格修改

### 3.1 视觉方向

采用“古风绘本＋重生逆袭”：深靛蓝作为场景和边框、暖宣纸作为阅读面、琥珀金强调晋升与主操作，少量朱砂用于印章。正误反馈仍使用明确语义色，并辅以文字或图形。

复用 Q 版人物与背景，优先重排 UI，不新增 AI 美术生成任务。标题可用本地楷体及中文衬线回退；正文、题目和数值使用清晰系统字体，不依赖手机装有 KaiTi，不以竖排书法承担正文。默认正文目标 16px、辅助文字 12–14px，主要点击区域至少 44×44 CSS px。

在 globals.css 统一颜色、卡片、按钮与间距，覆盖所有页面；处理现有系统深色偏好，避免深色背景与白色卡片失配。动画短促，支持减少动态效果偏好。

| 页面 | 风格与信息优先级 |
| --- | --- |
| 首页 | 人物与题名为中心；一行重生标语、一行玩法说明、一个进入按钮，取消单玩法的模式选择卡结构 |
| 官途 | 当前人物是中心；回答“我是谁、已有多少功名、下一步做什么” |
| 对局 | 书院 / 科考阅读面；NPC 轻量引导，题干与选项优先于装饰对白 |
| 结算 | 晋升体现“命运向前一步”；未中强调功名保留，避免失败等同人生重置 |
| 浏览页 | 册页与榜单样式，共用返回、标题与底部翻页结构 |

### 3.2 序章不阻断开局

首次进入且确认没有待恢复对局后，展示可跳过的单屏序章：“再睁眼，我又回到了一介布衣之时。 / 这一世，我要以诗词改写命运。”提供“开启这一世”和“跳过”。

使用版本化本地标记 rebirth-prologue:v1，在继续或跳过时记录；存储失败仍可进入游戏。恢复对局优先，不能被序章遮住却继续计时。更多面板提供回看入口，不新增服务端状态。

### 3.3 官阶叙事

只改 RANKS[].subtitle，不改官阶顺序、阈值与难度；新副标题仍遵守未来官阶迷雾规则。

| 官阶 | 新副标题 |
| --- | --- |
| 布衣 | 重活一世，从白身再起 |
| 童生 | 这一回，先叩开求学之门 |
| 秀才 | 纸上有名，命运开始不同 |
| 举人 | 此番登榜，不负重来一世 |
| 贡士 | 再向前一步，便是更大天地 |
| 进士 | 金榜题名，终于写下我的名字 |
| 翰林 | 手中这支笔，也能写出前程 |
| 知府 | 从无名布衣，到独当一面 |
| 侍郎 | 走到此处，我还要再进一步 |
| 丞相 | 曾经遥望的位置，如今已在脚下 |
| 皇帝 | 这一世，终以诗词问鼎天下 |

结算保留服务端分数、成功失败和缺口说明；短叙事不得重复堆叠 settleLine。服务端 persona 句式池本期保持现状。

### 3.4 封面与分享

首页推荐使用经核查的无字底图，通过 art-assets.ts 引用，以 HTML 排版新题名，随手机宽度换行；避免在缩小的正方形图片中阅读长书名。缩放优先保留人物，旧题名不能残留。

cover-title.py 同步维护新题名，用于需要嵌字封面的导出场景，不继续生成旧品牌图。真正修改图片时按适用图像工作流处理，本次方案阶段不编辑图片。分享标题用文本测量分两行排版，验证与人物、数据和底部说明不重叠。

## 4. 手机适配：完整内容的一屏

### 4.1 统一约束

1. 整个游戏默认无横纵滚动，弹层也不做长滚动容器；长列表、说明和收藏诗文采用显式分页。
2. 页面壳使用 100vh 回退、100dvh 优先，border-box 包含上下安全区；实施时核查 viewport 配置。
3. 顶栏、minmax(0, 1fr) 内容区、底部操作区组成页面；Flex/Grid 子项设 min-height: 0 与 min-width: 0。底栏留在布局流中，不覆盖正文。
4. overflow-hidden 仅作适配后的边界保护。禁止仅隐藏滚动条、裁掉内容或整体缩放界面。
5. 同时按宽度和高度适配：先缩装饰与空白，再收纳次要信息，最后分页，不缩小点击区域，不隐藏答题条件。
6. 任意长文本不可能全部同时塞入一屏。超长内容完整分页，不用省略号冒充完整；文本放大与极低高度同样走分屏，不禁用用户缩放。

### 4.2 官途主页

结构：顶栏 → 人物身份与目标 → 官途概览 → 事件位 → 辅助入口 → 主操作。

| 区域 | 360×640 设计预算 | 内容 |
| --- | --- | --- |
| 顶栏 | 44px | 返回、诗词逆命、皇榜 |
| 人物与身份 | 136px | 约 88–104px 立绘、官衔、短独白、功名进度与下一步目标 |
| 官途概览 | 60px | 当前、下一阶、迷雾概览；完整路线另开面板 |
| 事件位 | 40px | 事件名称、倍率与剩余时间；无事件时替换为成长提示，避免布局跳动 |
| 辅助入口 | 48px | 功名簿、诗词阁、更多；衣冠符合门禁时出现在更多面板 |
| 主操作 | 112px | 研习与科考并排，短说明；每日题独立一行 |
| 上下留白与间距合计 | 48px | 合计约 588px，不含安全区，剩余高度作为余量 |

这是原型预算，不是已测尺寸。按安全区与字体实测，余量不足先压人物装饰，不把区块尺寸固定死。大屏将多余高度让给人物与留白，不再纵向追加信息。

统计、最近战绩、完整路线进入分页面板。概览不能通过“共 11 阶”、占位、工具提示或可访问名称泄露隐藏终点。竞猜使用带文字的“猜官衔”入口，打开单屏面板；每日一次与 rankId >= 8 隐藏等规则不变。

主按钮仍称“研习”“科考”；未解锁时保留功名提示。顶阶按钮与题数沿用现有权威状态，不借文案改版改变考试语义。

### 4.3 对局：按最占空间的揭晓态设计

布局为“紧凑 HUD → 题面 → 四选项 → 操作 / 反馈槽”。删除重复题号与模式说明，先缩 NPC 对白和装饰。

- 四选项默认单列，兼容长作品名与诗句；题干、问法、选项不能 line-clamp。
- 底部预留反馈槽：PLAYING 放问同窗，REVEAL 原位替换为正误、功名与下一题，不再追加大气泡。
- 正确答案在原选项中完整标识，避免再重复长答案；详细点评仅在判题完成后开放阅读面板。
- 先用当前题库最长题面、最长选项及最长反馈组合测量。仍放不下时，将完整题干分成“读题 / 作答”两屏，作答屏四个选项仍须完整可见，提供返回题干入口。
- 极端长选项无法同时容纳时，使用完整选项阅读分页与显式选中确认，翻页不触发提交；常规题不得增加作答步骤。
- 阅读与翻页不重置、不暂停服务端时限。若真实题库多数题都要分页，说明布局失败，需重新分配高度，不能用分页掩盖。
- 保留自动下一题；揭晓态打开详细点评时暂缓客户端自动翻题，关闭后继续，避免新题在遮罩后开始计时。服务端时限规则保持原样。

### 4.4 结算

一屏保留“结果＋人物＋正确率 / 本局功名 / 累计功名＋下一步操作”。未中可直接重考，晋升突出新官衔与立绘，事件倍率并入功名区。

新增成就显示数量与详情入口，详情分页。分享只放“分享这一世”入口，点击后生成并打开预览，图片等比 contain 到剩余空间，关闭和保存始终可达；导出仍保留原图尺寸。图片或下载失败提供重试，不永久停留在生成中。

### 4.5 浏览页同样无滚动

| 页面 | 重构方式 |
| --- | --- |
| 功名簿 | 总览 / 月历 / 成就切换，不纵向叠加；月历按最多六周设计，补签与奖励另开面板 |
| 诗词阁 | 统计收入筛选面板，摘要分页，正文单独分页阅读，不在列表展开整首诗 |
| 皇榜 | 当前与历史榜切换；固定上一页 / 下一页；保留个人名次 |
| 衣冠 | 每页一套或有限张卡片，预览、解锁条件和装备按钮同屏 |

分页条固定占位，保留筛选与页码，切换筛选回第一页。优先分页现有接口返回数据；实施时核查返回数量与后续分页契约，不把前端分页冒充全量分页。接口只返回有限榜单时明确范围；若要求读取未返回数据，另列接口变更，不承诺现有接口已支持。

根据可用高度、字号和行高计算每页容量，避免硬编码固定条数后溢出。月历低高度或大字模式放不下时用周视图 / 日期分页，保留所有日期操作与触控区域。

### 4.6 面板通用规则

关闭、标题、翻页、确认固定占位；锁定背景，防止滚动穿透；支持焦点进入与恢复、键盘关闭和可访问标题。未展示分页内容移出交互与可访问树，不保留屏外焦点。横屏采用双栏或分屏，不仅提示旋转手机。

## 5. 门禁与架构边界

沿用[现有优化方案 §4.3](2026-09-20-poetry-rank-optimization-and-art.md)的终点门禁：拜相前不展示皇帝节点、登极说明及衣冠解锁信息，竞猜按原规则隐藏。名称不含皇帝只能避免一处冲突，不能证明全局无泄露。

本次要检查首页原有“皇帝登极大考”文案、封面人物与文字、分享默认模板、工具提示、alt 和可访问名称。不能用 CSS 隐藏代替不渲染。已解锁玩家的结算与分享可如实展示称号。这是叙事显隐，不宣称静态客户端资产具备保密能力。

保留纯逻辑层零 IO、服务端权威判题与功名官阶、现有加密包装。作答前不下发题目答案，判题后的现有反馈契约不变。路由、store、存储键、API 与枚举不随品牌迁移，资产引用统一经 art-assets.ts。

## 7. 验收与证据

### 7.1 视口与状态

- 必测 CSS 视口：360×640、375×667、390×844；补测 320×568 紧凑模式、844×390 横屏。尺寸指可用浏览器区域，不用手机型号代替。
- 自动化覆盖 Chromium 与 WebKit；具备设备时补测 iOS Safari、Android 浏览器工具栏展开 / 收起与安全区，无实机则记录限制。
- 首页首次 / 已有进度；官途 rank 0 / 8 / 9 / 10、有无事件、科考可用 / 锁定、每日题完成 / 未完成。
- 对局首题、长题、长选项、提示已用、提交中、答对 / 答错 / 超时、恢复、最后一题与自动翻题。
- 结算研习、每日题、晋升、未中、登极、多成就、事件、分享成功与失败。
- 浏览页空数据、满页、多页、长诗文与长昵称、六周月历、分页边界；所有面板及关闭路径。
- 异常覆盖加载、请求错误、存储不可用、图片字体加载失败、大字 / 200% 文本放大。

完整功能状态至少在 360×640 与 390×844 跑，其他尺寸覆盖最长内容、最多数据与门禁边界，不能只测布衣空白主页。

### 7.2 无滚动不等于适配成功

1. 检查根节点及 body 的 scrollHeight / scrollWidth 不超视口，实际滚动操作不会移动游戏页面。
2. 检查活动内容容器的实际尺寸与文本完整性，不能把溢出藏进 overflow-hidden。
3. 四选项、当前页题干、主操作、关闭与分页控件均在可用视口内；点击中心命中测试确认未被遮挡。
4. 检查横向溢出、换行、安全区、焦点及文字裁切；最长题、揭晓、多成就、分享图截图目视检查。
5. 逐页验证全部内容可达、末页可返回、筛选不丢失，并核查 rank 8 / 9 门禁变化。
6. 用确定性测试数据覆盖稀有状态；在本地生产构建至少跑通一次真实研习到结算，不以全量 mock 替代集成验证，不写真实玩家档案。

记录视口、状态、截图路径与失败原因。验收必须同时满足“没有滚动、没有裁切、操作可达、内容可完整阅读”。
